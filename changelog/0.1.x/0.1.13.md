# 0.1.13 — 2026-10-25

## Changed

- **`usda_search_foods` escapes the query characters FDC rejects** before sending it: each `/`, `[`, `]`, `{`, or `}` outside a well-formed regex (`/…/`) or range (`[a TO b]`) term, every `"` when the query holds an odd number of them, and each `(` or `)` that pairs with nothing. Text inside a balanced quoted phrase is left alone. Pasted descriptions like `trimmed to 1/8" fat` search literally instead of failing, and regex and range terms still work ([#21](https://github.com/cyanheads/usda-mcp-server/issues/21)); the `query` description lists the supported syntax.
- **An FDC 400 on search is now `query_syntax`** (`ValidationError`, recovery hint included) instead of a reasonless `InvalidParams` ([#21](https://github.com/cyanheads/usda-mcp-server/issues/21)).
- **Each FDC call retries within one 45 s deadline** (15 s per attempt, up to 3 retries, `Retry-After` included). A stalled upstream fails as `Timeout` with `data.reason: "retry_deadline_exceeded"`, or as `RateLimited` when the last attempt to complete before the deadline was a 429 ([#18](https://github.com/cyanheads/usda-mcp-server/issues/18)).
- **`usda_get_food` with `unit` and no `quantity` takes a default quantity**: 1 for `serving`, 100 for `g`, `oz`, `lb`, `kg`. `scaledTo` reports the quantity applied, `unit: "serving"` multiplies the first portion's weight by `quantity` (`quantity: 2` used to return one serving's values), and `unit: "serving"` with no `quantity` on a food with no portion data now fails `no_portion_data` instead of returning per-100 g values ([#16](https://github.com/cyanheads/usda-mcp-server/issues/16)).
- **`usda_compare_foods` documents `quantity` as an amount in `unit`**, not a gram basis (`unit: "oz"` alone compares per 100 oz) ([#16](https://github.com/cyanheads/usda-mcp-server/issues/16)).
- **The `Basis` line in `usda_get_food` and `usda_compare_foods` prints the exact `gramWeight`** (rounded to 4 decimals) instead of one decimal.
- **`usda_search_foods` serving line keeps FDC's `servingSizeUnit`** (`240ml`) and prints the size alone when FDC sends none, where it used to assume grams; `servingSize` and `servingSizeUnit` descriptions cover volume and other units ([#23](https://github.com/cyanheads/usda-mcp-server/issues/23)).
- **FDC-supplied text is escaped in `content[]`** across `usda_search_foods`, `usda_get_food`, `usda_get_foods`, and `usda_compare_foods` (mcp-ts-core `escapeMarkdownInline`); the framework escapes its own error and trailer Markdown.
- **Not-found detection uses the 404 status**, not the error message, in `usda_get_food` and `usda://food/{fdcId}` ([#22](https://github.com/cyanheads/usda-mcp-server/issues/22)).
- **`query_empty`, `query_syntax`, and `quantity_without_unit` are declared `severity: "notice"`**, so they log below `error`.
- **Docs and tooling:** per-client hosted-endpoint configs in the README, error tables and retry notes in `docs/design.md`, framework skills and `scripts/devcheck.ts` resynced to mcp-ts-core 0.13.16, Docker base images and `packageManager` on Bun 1.4.4.
