# 0.1.10 — 2026-09-16

## Added

- **`src/index.ts`** declares `sessionMode: 'stateless'` via `createApp()` — no handler opens a multi-round-trip input request. `createApp({ sessionMode: 'stateless' })` in `src/index.ts` declares the posture; an explicit `MCP_SESSION_MODE` value still overrides it.
- **`.env.example`** sets `MCP_SESSION_MODE=stateless` actively (previously commented at the `auto` default), documenting all three values.

## Changed

- **`@cyanheads/mcp-ts-core` upgraded to `^0.13.2`.**
- **Argument rejections now carry the structured error envelope** — an unrecognized key, wrong type, or missing required field returns `isError: true` with `structuredContent.error.code` `-32602` (`InvalidParams`) instead of a bare JSON-RPC error (mcp-ts-core 0.12.7).
- **The server card at `/.well-known/mcp.json` publishes the resolved session mode** under `_meta["io.github.cyanheads.mcp-ts-core/sessionMode"]` — `stateless` for this server (mcp-ts-core 0.13.2).
- **Bun engines floor raised to `>=1.4.0`**, matching the framework's own floor (mcp-ts-core 0.12.9).
- **README restructured** — an Overview section replaces the bare tool table, and each tool/resource gets its own `<sub>tool</sub>`/`<sub>resource</sub>` entry under "Capability reference," per mcp-ts-core 0.13.1's updated `polish-docs-meta` README reference.
- **Skill tree moved from `skills/` to `framework-skills/`** (mcp-ts-core 0.13.0) — a plugin host installing `.claude-plugin/` or `.codex-plugin/` no longer auto-loads this server's development skills; `.mcpbignore`, `.github/CONTRIBUTING.md`, and `docs/tree.md` updated to match.
- **Scaffold sync** — `package.json` gains an `audit:fix` script (`bun audit fix`); `.claude-plugin/plugin.json` adds `keywords` and a `cyanheads`-attributed `author`; `.github` issue forms and `CONTRIBUTING.md` pick up the framework's current triage/labeling conventions; `devcheck.config.json`, `changelog/template.md`, and several `framework-skills/` files resync to the framework template.

## Fixed

- **Plugin manifests no longer overwrite a user's API key on install** — `.claude-plugin/plugin.json` and `manifest.json` wire `USDA_FDC_API_KEY` through `${user_config.USDA_FDC_API_KEY}` with a declared `userConfig`/`user_config` option (`"default": ""`), replacing a literal `"your-api-key"` placeholder the plugin host previously set directly on the child process, silently overwriting a key the user had exported.
