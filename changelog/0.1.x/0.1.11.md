# 0.1.11 — 2026-09-21

## Added

- **CodeQL workflow** (`.github/workflows/codeql.yml`) — the one GitHub Actions workflow this project carries; verification stays local.

## Changed

- **Argument rejections carry `data.reason: "invalid_arguments"` and a synthesized `data.recovery.hint`**, rendered as a closing `Recovery:` line — an unknown key names the keys the tool accepts (mcp-ts-core 0.13.3).
- **Tool error `content[]` text closes with `(reason <reason>)`**, plus ` · retryable` / ` · not retryable` only when the error data carries a boolean `retryable`; `structuredContent` is unchanged (mcp-ts-core 0.13.5).
- **A case-style variant of a declared argument key is accepted** (`fdc_id` → `fdcId`) and a JSON-stringified array argument is repaired before validation; advertised `inputSchema` is unchanged and an undeclared key naming no declared key is still rejected (mcp-ts-core 0.13.4).
- **Server `instructions` name `usda_get_foods`** as the batch path alongside `usda_get_food` and `usda_compare_foods`.
- **Lookup-miss contract entries log at `notice` instead of `error`** — `usda_search_foods` `no_results`, `usda_get_food` `not_found` and `no_portion_data`, `usda_compare_foods` `too_few_foods`; the wire response, span status, and `mcp.tool.*` counters are unchanged, and `mcp.errors.classified` carries the declared `mcp.error.severity`.
- **`lint:mcp` reads `lint.truncationAllowlist` from `devcheck.config.json`** in place of an env var (mcp-ts-core 0.13.6); framework skills, issue forms, and agent docs resynced to match.

## Fixed

- **`.env.example`'s `MCP_HTTP_HOST` comment now states the actual default** (`127.0.0.1`) and documents the pre-existing `MCP_HTTP_MAX_BODY_BYTES`, resumability, and log rate-limit variables.
