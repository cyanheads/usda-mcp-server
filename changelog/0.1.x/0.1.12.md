# 0.1.12 — 2026-10-09

## Changed

- **Tool and resource error envelopes carry `data.requestId`**, and a tool error's text closes with `request <id>` (mcp-ts-core 0.13.10, cyanheads/mcp-ts-core#576).
- **A numeric string sent for a number argument is repaired before validation** (`fdcId: "169901"`, `pageSize: "2"` are accepted) (mcp-ts-core 0.13.14, cyanheads/mcp-ts-core#707).
- **A network failure reaching FoodData Central names the URL by origin only** (`https://api.nal.usda.gov/…`), not the request path (mcp-ts-core 0.13.12, cyanheads/mcp-ts-core#626).
- **A fractional number on an integer field is rejected with `Send fdcId as an integer, not a fractional number.`**, and argument-rejection hints keep field paths (mcp-ts-core 0.13.9, cyanheads/mcp-ts-core#499, cyanheads/mcp-ts-core#493).
- **MCP SDK 2.1 transport rules:** a 2026-07-28 POST without `MCP-Protocol-Version` is refused `400` / `-32020`, a JSON-RPC batch over 100 messages is refused, and on stdio, stdin EOF aborts in-flight requests (mcp-ts-core 0.13.9).
- **`ctx.log` notifications reach the client only at or above `MCP_LOG_LEVEL`** and carry `[REDACTED]` for sensitive fields (mcp-ts-core 0.13.11, cyanheads/mcp-ts-core#621, cyanheads/mcp-ts-core#630).
- **Removed the redundant `ctx.recoveryFor(...)` forwards** in `usda_get_food`, `usda_compare_foods`, and the `usda://food/{fdcId}` resource; the declared recovery hint text on the wire is unchanged (the framework fills it since 0.13.10).
- **Docker:** a `deps` stage on `$BUILDPLATFORM` cross-installs production dependencies, installs the OTel peers through `scripts/install-otel.ts`, and prunes musl-only packages with `scripts/prune-musl-packages.ts`; base images move to Bun 1.4.2.
- **`.env.example`** documents the opt-in `MCP_REQUEST_STATE_KEY`, `LOG_TOOL_FAILURE_PAYLOADS`, `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, `LOG_LLM_INTERACTIONS`, and the OTLP base, traces, metrics, and logs endpoint variables (documentation only, defaults unchanged).
- **Repo and tooling:** `.gitignore`/`.dockerignore` cover every `.env*`, `.mcpbignore` excludes `.cache/`, `coverage/`, `tests/`, `logs/`, and `docs/idea.md`, `package.json` `files` adds `!dist/*.mcpb`, `packageManager` is `bun@1.4.2`, CodeQL runs one job per language, framework skills and scripts resynced, `CLAUDE.md`/`AGENTS.md` wording and README badges updated.

## Fixed

- **`server.json` HTTP entry now starts the HTTP transport.** Both npm entries passed `run start:stdio` / `run start:http` as `packageArguments` under `runtimeHint: "bun"`, so a registry client's HTTP entry did not start the HTTP transport; the arguments are removed, `runtimeHint` is `"npx"`, and the `streamable-http` entry sets `MCP_TRANSPORT_TYPE` to `"http"`.
