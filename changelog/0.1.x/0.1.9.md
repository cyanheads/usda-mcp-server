# 0.1.9 — 2026-08-25

## Added

- **`src/index.ts`** declares `cacheHints` for `tools/list`, `resources/list`, and `resources/templates/list` (1 hour, public) — the tool/resource listing is fixed at build time, so a client on protocol revision 2026-07-28 may cache it for the life of the deployment.
- **`usda://nutrients`** resource declares its own `cacheHint` (1 hour, public) — the bundled nutrient table never varies by caller.

## Changed

- **`@cyanheads/mcp-ts-core` upgraded to `^0.12.3`**, adopting the framework's MCP SDK v2 migration (`@modelcontextprotocol/sdk` → `@modelcontextprotocol/server`/`client`).
- **Tool inputs are strict at the root.** An unrecognized argument key is now rejected by name instead of silently dropped; all five tools advertise `additionalProperties: false` under JSON Schema 2020-12.
- **Advertised `outputSchema` now declares the error envelope**, so a client that validates `structuredContent` without checking `isError` no longer misreads an error result.
- **Bun pinned to `1.4.0`** — `Dockerfile` (both stages) and `package.json` `packageManager`; the build stage adds `--platform=$BUILDPLATFORM` since Bun 1.4.0 aborts under qemu-emulated amd64 during a multi-arch `buildx` build.
- **`.env.example`** documents `MCP_SESSION_MODE=stateless` explicitly — the framework default changed from `stateful` to `auto` (itself resolving to `stateful`); this server has no multi-round-trip input handlers and stays stateless, matching `Dockerfile`.
- **`fdc-service.ts`** drops two `as unknown as RequestContext` casts now that `Context` extends `RequestContext` directly.
