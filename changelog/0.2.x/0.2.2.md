# 0.2.2 — 2026-11-14

## Added

- **`usda_search_foods`** matches a bare 12–14-digit query with a valid check digit against every digit form FDC stores that GTIN in, in one upstream call; rows keep the stored `gtinUpc` ([#41](https://github.com/cyanheads/usda-mcp-server/issues/41)).
- **`usda_compare_foods`** returns `deferredIds`, the IDs FDC did not return before the call's deadline, with a notice on both surfaces; the comparison leaves them out ([#42](https://github.com/cyanheads/usda-mcp-server/issues/42)).

## Changed

- **A `/foods` batch attempt that times out at 15 s** is refetched as one request per ID, at most 10 in flight per process, all inside the call's 45 s deadline. A refetched ID whose retries run out on a transient failure (5xx, 429, network) is deferred like a deadline miss when another ID answered; a non-transient 4xx, or a complete body of the wrong shape, fails the call ([#42](https://github.com/cyanheads/usda-mcp-server/issues/42)).
- **`usda_get_foods`** `deferredIds` also lists fetched IDs FDC did not return before the deadline, ahead of the IDs past the first 20, and the notice names them ([#42](https://github.com/cyanheads/usda-mcp-server/issues/42)).
- **`usda_compare_foods`** raises `too_few_foods`, with `deferredIds` in its data, when even answers for the deferred IDs could not make 2 foods, and `retry_deadline_exceeded` only when they could ([#42](https://github.com/cyanheads/usda-mcp-server/issues/42)).
- **Record requests** (`usda_get_food`, `usda://food/{fdcId}`, a one-ID batch, a refetch) are no longer cut at 15 s and run to the call's 45 s deadline: a first attempt that hangs now fails at 45 s, where 0.2.1 retried at 15 s ([#42](https://github.com/cyanheads/usda-mcp-server/issues/42)).
- **A complete FDC 200 body that is not JSON** is `ServiceUnavailable` with `retryable: false` and sent once; it was a parse error, retried, and classified as invalid input.

## Fixed

- **`usda_get_food` portions** follow FDC's display order, ascending `sequenceNumber` with unnumbered portions last, so `servingInfo`, `unit: "serving"`, `allPortions`, and the `usda://food/{fdcId}` `portions` no longer take whichever portion FDC lists first ([#40](https://github.com/cyanheads/usda-mcp-server/issues/40)).
- **`usda_get_foods` and `usda_compare_foods`** failed `retry_deadline_exceeded` on 20 Foundation IDs, or 5 in a comparison; they now return the foods FDC answers in time ([#42](https://github.com/cyanheads/usda-mcp-server/issues/42)).
- **`retry_deadline_exceeded`** reads `FDC <path> request exceeded …` and carries a recovery hint on every tool and the resource.
- **`usda_search_foods` `no_results` for a bare code** reads as a code that no record stores and points to a name search with `dataType: ["Branded"]`; it names the query, not the digit forms sent.
